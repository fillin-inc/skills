# テンプレート記入

日報・週報・報告書などの Markdown テンプレートを実行時に受け取り、回答欄が空いている箇所を質問として上から順に尋ね、回答を書き込んだ Markdown ファイルを作る。テンプレート自体は変更しない。

質問と回答は淡々と進める。質問文はテンプレートの文字列をそのまま使う。回答は音声入力の場合もあるため、打ち間違い・変換ミス・フィラーだけを整えて書き込み、内容は変えない。

以下で `$SKILL_DIR` は、この SKILL.md が置かれているディレクトリの絶対パスを指す。

## Phase 1: オプションの解決

依頼からテンプレートと出力先の指定を読み取り、次を実行する。

```sh
"$SKILL_DIR/scripts/parse-options.sh" <template.md> [--output <path>]
```

出力の `TEMPLATE` と `OUTPUT_PATH` を以降のフェーズで使う。`--output` が無ければ、`OUTPUT_PATH` には作業ディレクトリの `<テンプレート名>-<日付>.md` が、既存ファイルと重ならない名前で入る。

テンプレートが依頼から特定できない場合だけ、パスをユーザーに尋ねる。示されたらそれで Phase 1 を実行し、中止されたら終了する。

スクリプトの呼び出しが失敗したときは次のように扱う。

- シェルが 127 で終了した: skill の同梱ファイルが欠けているので、再インストールを案内して停止する
- `exit 64`: stderr のメッセージを示す。Markdown 以外のテンプレートなら、この skill は Markdown だけを扱うことを伝える。指定を直してもらえたら Phase 1 をやり直し、中止されたら終了する
- `exit 66`: テンプレートが見つからない。パスを確認してもらい、新しいパスが示されたら Phase 1 をやり直し、中止されたら終了する
- 10 秒を超えて戻らない: 中断する。このスクリプトはネットワークもサブプロセスも使わないため通常は起きない。渡した引数を確認するよう伝えて停止する

## Phase 2: 質問の洗い出し

`TEMPLATE` を読み、[`references/template-rules.md`](references/template-rules.md) の「質問になる箇所」に従って、質問を出現順に並べる。一覧はユーザーに示さず、そのまま Phase 3 へ進む。日報のように毎日繰り返す記入では、質問に入る前の確認が毎回の手間になるためである。質問の過不足は Phase 4 の確認で気づける。

質問が 1 つも無い場合は、回答欄の空いた見出し・ラベル・チェックリスト・表セルが見つからなかったことを伝えて終了する。

## Phase 3: 1 問ずつ質問する

並べた順に、1 回の発話で 1 問だけ尋ねる。

- 形は `[3/7] <質問文>` とする。質問文はテンプレートの見出し・ラベルの文字列をそのまま使い、言い換えや前置きを付けない。補足の HTML コメントがあれば次の行に添える
- チェックリストは、選択肢に `1.` から番号を振って並べ、複数選べることを添える。テンプレートで既に `[x]` の選択肢には `(選択済み)` と付ける。ホストに選択肢を提示する UI があればそれを使ってよい
  - 番号でも選択肢の文字列でも受け付ける
  - 選択肢に無い回答は、そのまま追加の選択肢として受け付ける
- 自由記述の回答は複数行でも受け付ける
- 回答の代わりに次の指示を受け付ける
  - 「スキップ」: その箇所をテンプレートのまま残して次へ進む
  - 「戻る」: 1 つ前の質問を聞き直す。最初の質問なら同じ質問を聞き直す
  - 「中止」: 何も書き出さずに終了する
- 回答の内容を評価したり、聞き返したりしない。途中で聞き返すと、テンポよく答えていく流れが止まるためである。気になる点は Phase 4 の確認でまとめて示す。受け取った回答は [`references/template-rules.md`](references/template-rules.md) の「回答の整え方」に従って整え、整えた形で保持する

## Phase 4: 確認

全質問の回答を、整えた後の形で `質問文: 回答` の一覧にして示し、この内容で書き出してよいか確かめる。

- 回答を整えた箇所があれば、一覧の後に `方が痛い → 肩が痛い` の形で並べる。フィラーの除去と句読点の補完は個別に並べず、行ったことだけを 1 行で添える
- 直すべきか判断が付かなかった箇所があれば、それも併せて示す

ユーザーの応答に応じて次のように進む。

- 了承されたら Phase 5 へ進む
- 特定の質問の修正を求められたら、その質問だけ聞き直して一覧を示し直す
- 整えた箇所を元に戻すよう求められたら、その箇所だけ元の回答に戻して一覧を示し直す
- 中止されたら何も書き出さずに終了する

## Phase 5: 書き出し

テンプレートの本文に [`references/template-rules.md`](references/template-rules.md) の「回答の書き込み」に従って回答を反映し、`OUTPUT_PATH` に新規ファイルとして保存する。テンプレートのファイルは書き換えない。

保存に失敗した場合 (書き込み権限が無い・親ディレクトリが無い等) は、理由を伝えて別の出力先を尋ねる。示されたらそこへ保存し、中止されたら完成した本文をそのまま応答に示して終了する。

## Phase 6: 報告

出力先のパスと、スキップした質問を短く伝える。
