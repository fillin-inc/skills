# Web 調査レポート

自然言語の依頼から調査テーマと読者を捉え、検証可能な資料ファイルを作る。

## 必須条件

- Web 検索を実施し、重要な事実は実際に開いて確認した情報源で裏付ける。
- タイトルの直後に「エグゼクティブサマリー」を置く。
- 本文中の重要な事実から対応する情報源へ辿れるようにする。HTML は引用番号と末尾の「出所」、Markdown は引用番号と末尾の `# Citations` を使う。
- 情報源にはページ名、発行元、URL、公開日または更新日(判明する場合)、参照日を記載する。
- 図を使う場合は Mermaid 記法だけを使う。SVG、Canvas、ASCII art、画像生成による図へ置き換えない。

Web 検索または出所の省略を求められた場合は、この skill の必須条件と両立しないことを説明して停止する。調査済み資料であるかのような成果物は作らない。

## 出力形式

既定は HTML とする。ユーザーが Markdown を指定した場合は Markdown にし、両方を明示した場合だけ両形式を作る。HTML と Markdown 以外の形式を指定された場合は、この skill の対象外であることと選択可能な 2 形式を伝えて停止する。出力先の指定がなければ、作業ディレクトリに内容を表す短い kebab-case 名で保存する。

### HTML

- UTF-8 の単一 HTML ファイルにし、セマンティックな見出し構造、十分なコントラスト、読みやすい行長、レスポンシブ表示、印刷用スタイルを備える。
- 引用番号は該当する出所へのページ内リンクにする。外部 URL は通常のリンクとして開けるようにする。
- Mermaid を使う場合は `<pre class="mermaid">` に Mermaid ソースを置き、Mermaid.js を読み込んで初期化する。Mermaid.js 以外の描画ライブラリを追加しない。
- 情報源から取得した HTML やスクリプトをそのまま埋め込まない。

### Markdown(OKF v0.1 の基本形)

- UTF-8 の OKF concept document とし、1 行目から parse 可能な YAML frontmatter を置く。
- frontmatter には空でない `type: Research Report` を必須とし、`title`、1 文の `description`、`tags`、`timestamp` を含める。`timestamp` は UTC offset 付き ISO 8601 にする。
- 資料が説明する対象に正規 URI がある場合は `resources` を追加する。値を埋めるために出力ファイルのパスや代表的な出典 URL を代用しない。
- 重要な主張には `[1]` のような引用番号を付け、本文末尾の `# Citations` に同じ番号で情報源を列挙する。各項目にはページ名、発行元、URL、公開日または更新日(判明する場合)、参照日を記載する。
- frontmatter と本文内の参照には通常の Markdown リンクを使う。
- 図は `mermaid` の fenced code block にする。

frontmatter は次の形にする。`resources` は対象の正規 URI がある場合だけ追加する。

```yaml
---
type: Research Report
title: <資料タイトル>
description: <1 文の概要>
resources:
  - <対象の正規 URI>
  - <対象の正規 URI>
tags: [research, <トピックタグ>]
timestamp: <UTC offset 付き ISO 8601 日時>
---
```

## 進め方

1. テーマ、想定読者、目的、対象期間、希望形式を依頼から読み取る。テーマが特定できない場合だけ質問する。回答でテーマが示されたら続行し、中止されたら終了し、別案が示されたら新しい依頼としてこの項から判定し直す。それ以外は妥当な前提を置いて資料中に明記する。
2. 検索語を複数の観点に分けて Web 検索する。一次情報、公式文書、原論文、公的統計を優先し、主要な主張は可能な範囲で独立した情報源と照合する。
3. 各情報源を開き、主張を直接裏付ける箇所と発行元、日付、URL を記録する。検索結果のスニペットだけを根拠にしない。
4. 事実と推論を区別して構成する。HTML はエグゼクティブサマリー、本文、出所の順にし、Markdown は OKF frontmatter、タイトル、エグゼクティブサマリー、本文、`# Citations` の順にする。図が理解を明確に改善する場合だけ Mermaid を追加する。
5. ファイルを保存し、必須条件、引用の対応、リンク、文字化け、レイアウトを確認する。HTML は利用可能なローカルプレビューで開き、表示も確認する。
6. 出力ファイルの絶対パス、形式、使用した情報源数、プレビュー結果を報告する。

## 失敗時

- Web 検索が利用できない場合は作成を停止し、検索不能であることと、再試行またはユーザー提供資料を使う選択肢を伝える。
- 検索が失敗した場合は、検索語を狭めるか別の一次情報へ切り替えて一度再試行する。重要な主張を裏付けられなければ停止し、失敗内容を伝える。
- 各検索とページ取得は 60 秒を上限にする。タイムアウトした場合は中断し、検索範囲を狭めて一度再試行する。再度タイムアウトしたら停止する。
- 検索結果が 0 件の場合は検索失敗と区別して明示し、検索語を変えて一度再試行する。それでも 0 件なら停止する。
- プレビュー機能が利用できない場合は、ファイルの絶対パスとブラウザで開けることを伝える。
- プレビューは 30 秒を上限にする。プレビューが失敗またはタイムアウトした場合は中断し、未確認であることとファイルの絶対パスを伝える。確認済みとは報告しない。
- Mermaid.js が利用できないか読み込みに失敗した場合は Mermaid ソースを残し、図の描画が未確認であることを報告する。読み込みが 30 秒を超えた場合はプレビューを中断し、同じ扱いにする。
