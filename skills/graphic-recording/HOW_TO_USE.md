# graphic-recording の使い方

## 概要

テキストやファイルの内容を読み解き、A4 比率のグラフィックレコーディング画像 1 枚を生成する単一フローの skill です。サブコマンドは持たず、位置引数とフラグだけを取ります。

**成果物は画像ファイルに限られます**。ホストエージェントが画像を新規生成できない場合、この skill は HTML や構成案などの代替物を作らずに停止します。

## 起動トリガー

- 「このメモをグラレコにして」
- 「議事録を 1 枚絵にまとめて」
- 「グラフィックレコーディングを作って」
- 「印刷して配れる図解画像にして」

## 位置引数

入力は位置引数で渡します。複数指定でき、テキストとファイルパスを混在させられます。

- 既存ファイルを指すパス → 入力ファイルとして読み込まれます
- それ以外の文字列 → 入力テキストとして扱われます

判定は `scripts/parse-options.sh` が `[ -f ... ]` で行うため、存在しないパスを渡すとテキスト扱いになります。

位置引数を省略した場合、skill は何を題材にするかをユーザーに尋ねます。

## フラグ一覧

| フラグ | 値 | default | 説明 |
|---|---|---|---|
| `--tone` | `business` / `standard` / `pop` / `mono` | `standard` | 画風のプリセット |
| `--orientation` | `landscape` / `portrait` | `landscape` | 用紙の向き |
| `--output` | パス | 未指定 | 保存先。省略時は作業ディレクトリに内容を表す kebab-case 名で保存 |
| `-h`, `--help` | - | - | `parse-options.sh` の usage を表示 |

`--tone=business` のような `=` 区切りの記法も受け付けます。

列挙値以外を渡した場合、`parse-options.sh` は `exit 64` で usage を表示して失敗します。

## トーン別の使い分け

| トーン | 想定用途 | 特徴 |
|---|---|---|
| `business` | 社内報告、役員向け資料、提案書の添付 | 低彩度のネイビー / グレー基調、直線的なフレーム、装飾を排した端正なゴシック |
| `standard` | 一般的な議事録・勉強会レポート | 紙地に 5 色マーカー、付箋・吹き出し・手描き矢印 |
| `pop` | ワークショップ、イベントレポート、社内報 | 高彩度 5〜6 色、大きな手書き文字、デフォルメ人物 |
| `mono` | 白黒印刷、コピー配布、FAX 送付 | 黒 1 色 + ハッチング。グレー塗りに頼らずコントラストで区別 |

依頼文に用途の文脈があれば、skill 側から対応するトーンを提案します。提案を断れば `standard` のまま、別のトーンを指定すればその指定で進みます。

各トーンの配色・線・文字・要素・避けるものの具体的な指示文は `references/presets.md` にあります。表現を変えたいときはこのファイルを編集してください。`scripts/parse-options.sh` は「どの節を読むか」を返すだけで、指示文そのものは持ちません。

## 用紙比率

A4 比率 (1:√2 ≒ 1:1.414) に寄せます。厳密な A4 実寸への一致は保証しません。

| 向き | 縦横比 | フォールバック | ピクセル指定 |
|---|---|---|---|
| `landscape` | `1.414:1` | `4:3` → `3:2` | 1754 x 1240 |
| `portrait` | `1:1.414` | `3:4` → `2:3` | 1240 x 1754 |

画像生成ツールが縦横比パラメータを持つ場合は、プロンプト内の指定に加えてそのパラメータにも同じ値が設定されます。

## 使用例

```bash
# 議事録ファイルを既定のトーン・横向きでグラレコ化
議事録.md をグラレコにして

# 役員向けに、白黒印刷を前提とした縦 1 枚
docs/plan.md をグラレコにして --tone mono --orientation portrait

# その場のテキストから、社内報告用のトーンで出力先を指定
"Q3 の振り返り: 売上は前年比 120%、課題は採用" をグラレコにして --tone business --output out/q3-review.png
```

## 実行できない環境について

Phase 0 の能力ゲートは、ホストエージェントが自分のツール一覧を確認する形で行われます。シェルから検出できる性質のものではないため、スクリプトによる判定は行いません。

画像を生成できない環境では次のように振る舞います。

- 以降のフェーズへ進まず停止する
- HTML / SVG / Mermaid / 構成案などの代替物を作らない
- 画像生成に対応したモデルまたはコーディングエージェントでの再実行を案内する

日本語テキストの描画品質は画像生成モデルに依存します。文字の崩れが許容できない場合は、日本語描画に強いモデルを選んで実行してください。skill は Phase 5 で生成画像を開いて文字の崩れを確認し、崩れがあれば 1 回だけ再生成を試みたうえで、直らなかった点をそのまま報告します。
