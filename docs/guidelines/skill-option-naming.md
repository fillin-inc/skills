# Skill オプション命名規約

## 概要

skill 群が共有する CLI フラグの語彙を 1 ページに集約する。`--auto` / `--fix` / `--fix --auto` の意味と、それぞれが想定する skill 横断の振る舞いを定義する。新規 skill を追加するとき・既存 skill にフラグを足すときの参照点とする。

## 背景

skill が増えると、複数の skill にまたがって「無人完走」と「レビュー → 修正モード」を表現する必要が出てくる。skill ごとに `--auto-fix` のような複合フラグや `xxx-fix` のような別 skill で表現すると、意味は揃っているのに表現が分散し、利用者が skill ごとに語彙を覚え直すことになる。本規約は全 skill が同じ語彙を使うための合意を明文化する。

## 規約

### `--auto`

- **意味**: skill 内のユーザー確認プロンプト・人間判断項目をすべて skip して無人完走させる。
- **対象**: 確認・選択・承認のための対話を持つ skill 全般。
- **典型例**:
    - コミットメッセージの承認質問を skip する
    - PR 作成前の最終確認を skip する
    - 「人間の判断が必要」と分類した項目を全件 skip する
- **意味の不変条件**: `--auto` は「破壊的操作の追加実行」を意味しない。あくまで「すでに skill が行う対話の skip」のみ。`--auto` を付けても skill が新たな書き込み権限を得るわけではない。
- **下流 skill への伝播規則**: `--auto` 付きで起動された skill が下流の子 skill を呼ぶ場合、下流呼び出しにも `--auto` を伝播する(呼び出し元が `--auto` なしで起動された場合は下流も対話モードで呼び、確認プロンプトをそのまま表示する)。伝播するのは「対話 skip の意思表示」のみで、`--fix` のような別軸のモード遷移フラグは `--auto` の有無と独立に付与してよい。

### `--fix`

- **意味**: review skill において「レビュー結果を集めて終わる」のではなく「レビュー結果に基づいて自動修正・コミット・スレッド解決まで踏み込む」サブフローに遷移する。
- **対象**: レビュー系 skill。
- **典型例**:
    - レビュー結果から自動で対処できる findings を順に修正・コミットする
    - 外部レビューの完了を待機してから、レビューコメントへの修正を連鎖させる
- **依存関係**: `--fix` が待機対象や入力を前提とする場合(例: 外部レビューを依頼していないと待機対象が存在しない)は、前提となるフラグが無いときに引数解析スクリプトで fail-fast に拒否する。

### `--fix --auto`

- **意味**: 「レビューモードに入り、人間判断項目を skip して自動修正を完走する」。
- **対象**: review skill のうち `--fix` が定義されているもの。
- **下流への伝播**: `--fix --auto` で起動された skill が下流 skill を呼ぶ際は、下流側にも `--auto` を伝播する。`--fix` 単独(`--auto` なし)で起動された場合は、下流の修正 skill を連鎖させるときも下流を対話モードで呼び、確認プロンプトを省略しない(上の `--auto` の伝播規則と同じ)。

## 設計上の不変条件

- **複合語フラグを導入しない**: `--auto-fix` のように `--auto` と `--fix` を結合した単一フラグは導入しない。両者は直交した軸(A: 対話 skip、F: モード遷移)であり、独立フラグとして表現することで意味の合成を一意にする。
- **既存 skill の `--auto` の意味を変えない**: 新規 skill が `--auto` を採用する場合、上記「確認プロンプト skip」の意味から逸脱しない。例えば「自動的に何かを生成する」用途で `--auto` を再利用してはならない。
- **レビュアーの切り替えは `--reviewer` で表現する**: 複数のレビュアーを持つ review skill は、レビュアーごとに別 skill を作らず `--reviewer <name>` で切り替え、`--fix` / `--fix --auto` の語彙に揃える。
