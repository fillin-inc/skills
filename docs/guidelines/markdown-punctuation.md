# Markdown 括弧の全角/半角ルール

本リポジトリの skill が出力する markdown 成果物、および `docs/` / `AGENTS.md` / `README.md` などの内部ドキュメントで使用する **括弧** の運用ルールを SSOT として定める。

**本文の括弧は半角に統一する。全角括弧 `（` `）` は使わない。**

読点 `、` / 句点 `。` / 中黒 `・` 等の句読点は本ガイドラインの対象外とする。カンマ `,` / ピリオド `.` への一律置換もしない。本ドキュメントで規定するのは括弧 `（）` / `()` のみ。

## 適用範囲

- `skills/**/references/*.md` の生成テンプレート、および skill が生成する markdown 成果物
- `docs/` 配下のドキュメント
- `AGENTS.md` / `README.md` / `HOW_TO_USE.md` 等のガバナンス系ドキュメント

## 具体ルール

### ルール 1: 本文の括弧は半角

本文中の括弧は例外なく半角にする。日本語のみの補足であっても、見出しの装飾であっても全角は使わない。

- OK: `IP アドレス (IPv4)` / `料金 (¥1,200 / 月)` / `強み (事実)` / `## 前提 (読者向け)`
- NG: `IP アドレス（IPv4）` / `強み（事実）` / `## 前提（読者向け）`

かつては「日本語のみなら全角可」「意図的な装飾なら全角可」という例外を設けていたが、次の理由で廃止した:

- 「意図的な装飾か否か」は主観判定でありレビューで反証できない。機械検証もできない
- 例外を残した結果、明文化されていたにもかかわらず 4,412 箇所が違反状態で放置され、同一行に半角と全角が混在していた

例外を持たないことで、ルール全体が `make lint` で機械検証できる状態になっている。

### ルール 2: 原文を残したい箇所はインラインコードで書く

唯一の例外がインラインコード (`` `...` ``) の内側。**全角であること自体が意味を持つ記述** を書くための逃がし場所として使う。

- ルールそのものの説明: 全角括弧 `（` `）` は使わない ← この `（` `）` は保持される
- NG 例の提示: `` - NG: `IP アドレス（IPv4）` ``
- 全角 → 半角変換の仕様説明: `` `（１）` → `(1)` ``

**インラインコードは無条件の逃がし場所ではない**。生成物の書式 (`## 第○条(タイトル)` のような出力見出し)、skill が表示するメッセージ、プレースホルダの説明をインラインコードで書く場合は、本文と同じく半角にする。lint が検出できない領域なので、書く側が意識する必要がある。

コードブロック (```` ``` ````) と引用ブロック (`>`) は **検査対象に含める**。理由は次のとおり:

- **コードブロック**: `markdown` / `yaml` フェンスは skill の出力テンプレート本体であり、全角を残すと生成物に混入する。`bash` / `sh` フェンスの全角括弧も実測ではすべてコメントか `echo` の出力メッセージ内にしか現れず、実行構文には影響しない
- **引用ブロック**: 本リポジトリの `>` は外部原文の引用ではなく `> **Note**:` 形式の注記ブロックとして使われており、原文尊重の対象にあたらない

外部から引用した原文を一字一句保持する必要が生じた場合は、インラインコードで囲むか、引用であることを明示したうえで個別に判断する。

### ルール 3: 半角括弧の直前スペースは詰める (開き側のみ)

半角括弧 `(` の直前が単語 / 日本語文字 / 閉じ記号 (`**` bold-close, `` ` `` inline-code close 等) の場合、間に半角スペースを入れず詰める。

- OK: `**逆引き(PTR)**` / `**Budget**(予算)` / `工数(人日)`
- NG: `**逆引き (PTR)**` / `**Budget** (予算)` / `工数 (人日)`

**閉じ側 `)` の後ろ** はスペース有無を規定しない (`(compat) or 不明` のように空きを保つ方が読みやすい場合が多いため一律には詰めない)。

**例外** (詰めない):

- markdown 記法の marker 直後: 行頭リスト marker `- (` / `* (` / `+ (`、見出し `# (` / `## (`、blockquote `> (`、テーブル区切り `| (` は詰めない (記法自体が空きを必要とするため)
- 開き括弧の直後の入れ子: `((...))` / `[(...]` のような直後 open は詰めない
- インラインコード内: ルール 2 に従い原文保持

このルールは markdown 記法との区別が必要なため lint には含めていない (人手で守る)。

## セルフチェック手順

### 機械検証される部分 (ルール 1 / 2)

全角括弧は `make lint` に含まれる `bin/lint-markdown-punctuation.sh` が検出する。除外はインラインコードの内側だけで、コードブロックも引用行も検出対象。

```sh
sh ./bin/lint-markdown-punctuation.sh          # 検証のみ
sh ./bin/lint-markdown-punctuation.sh --fix    # 全角括弧を半角へ一括置換
```

置換は開き / 閉じの対応を解決せず 1 文字ずつ行うため、入れ子 (`（A（B）C）`) でも複数行にまたがる括弧でも結果が壊れない。

### 人手で判定する部分 (ルール 3)

開き括弧直前のスペースは lint に含めていない。`rg ' \(' path/to/file.md` で確認し、ルール 3 の例外に当たらないものは詰める。
