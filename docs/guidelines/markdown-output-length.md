# Markdown 成果物の分量較正ガイドライン

skill が生成する markdown 成果物について、**出力分量をどこまで指定するか** の線引きを SSOT として定める。

Claude Opus 5 の公式 prompting ドキュメントは「files that Claude writes to disk are often longer than on prior models」として、ディスク書き出し成果物に対する明示的な分量較正文の追加を指示している。一方 Claude Fable 5 のドキュメントは「skills developed for prior models are often too prescriptive and can degrade output quality」として過剰指定を警告している。この 2 つを両立させるため、較正を **モデル都合** と **プロダクト都合** の 2 種類に分けて扱う。

## 適用範囲

- `skills/**/references/*template*.md` / `*output-format*.md` 等、markdown 成果物の構造を定義するテンプレート
- テンプレートファイルを持たず `SKILL.md` 本文に出力構造を直接定義している skill
- 対象外: markdown ファイルを書き出さない skill(レビュー系・監査系で chat 出力のみのもの)、`docs/` 配下の内部ドキュメント(本ガイドライン自体を含む)

## 2 種類の較正

### モデル都合の較正(水増し抑止) — 短文に留める

Opus 5 が旧モデルより長い成果物を書きがちな挙動を打ち消すためだけの較正。**媒体側に分量の制約は無い**。テンプレートの節構成を守らせたうえで、各節が実質を持つことだけを要求する。

- **1〜2 行の短文に留める**。何字以内・何節までといった数値制約は入れない
- 「どういう書き方が水増しか」を列挙しすぎない(埋め草の要約節 / 定型文 / 冗長な繰り返し の 3 例程度で十分)
- 節ごとに繰り返し書かない。テンプレート冒頭に 1 回だけ置く

標準較正文(これをそのまま使ってよい):

```markdown
各節は実質を満たす分量に留め、埋め草の要約節・定型文・冗長な繰り返しで水増ししない。
```

**原本の転記だけを行う skill** — 入力文書から項目を書き写すのが成果物のすべてで、分析・推奨・次アクションを一切生成しないもの — に限り、次の変形を使ってよい。

```markdown
各節は原本にある事実だけで構成し、埋め草の要約節・定型文・冗長な繰り返しで水増ししない。
```

この変形を **分析・提案を生成する skill に適用してはならない**。「事実だけで構成」は所見・リスク評価・推奨アクション・次の一手といった生成節を「入力に書かれていないから出力しない」方向に誘導し、その skill の主要成果を形骸化させる。転記主体かどうかは、テンプレートに「入力から導出する判断」を書く節が 1 つでもあるかで判定する — あれば標準較正文を使う。

### プロダクト都合の較正(媒体制約) — 詳細指定を許容する

成果物を載せる媒体・用途そのものに分量の制約があるケース。これはモデルの挙動とは無関係な仕様なので、字数・枚数・見出し本数といった **数値での詳細指定を許容する**。

典型例:

- 投稿プラットフォームの表示上限に合わせた字数制約(フィードでの省略境界・平均滞在時間に由来する二段制約など)
- 印刷・配布を前提とした紙面制約(A4 1 枚に収める、など)
- スライドの枚数・1 枚あたりの要素数

**数値の根拠を必ず併記する**。「なぜその数値なのか」が書かれていない制約は、後で媒体仕様が変わったときに更新可否を判断できなくなる。

プロダクト都合の較正は **その skill の媒体制約に固有** なので、他 skill へ横展開しない。ある skill の字数帯を別 skill にコピーするような運用は誤り。

## 判定フロー

1. その skill は markdown ファイルを書き出すか → No なら対象外
2. 成果物を載せる媒体・用途に固有の分量制約があるか
    - Yes → プロダクト都合の較正。数値を含む詳細指定を書く
    - No → モデル都合の較正へ進む
3. モデル都合の較正では、その skill が転記専用か(分析・推奨・次アクションを生成する節が 1 つも無いか)を判定する
    - 転記専用 → 転記変形を置く
    - それ以外 → 標準較正文を置く
4. 既に較正文がある場合は追加しない(重複させない)

## 配置場所

- テンプレートファイルに導入文(指示文)の領域がある skill: その導入文に 1 行足す
- テンプレートファイルが無い skill: `SKILL.md` の出力構造を定義している節の冒頭、または出力手順の注記に 1 行足す
- **テンプレートファイル全体が出力本文そのもので、指示行を置く余地が無い skill**(先頭が frontmatter から始まり、書いた内容がそのまま成果物に混入するもの): テンプレートには足さず、`SKILL.md` 側でそのテンプレートを読み込む手順に 1 行足す

いずれも **出力構造の直前** に置く。skill 本文の離れた場所に置くと、テンプレートを読んで書き始める時点でコンテキストから外れる。

テンプレート冒頭が「指示コメント」(`<!-- ... -->` などで囲まれ、出力には現れない領域)になっている場合は、そのコメント内の末尾に置いてよい。

## セルフチェック

markdown 成果物を書き出す skill を新規追加・改修したときは次を確認する。

1. 出力テンプレート(または SKILL.md の出力構造節)に較正文が 1 箇所あるか
2. モデル都合の較正が 2 行を超えていないか
3. モデル都合の較正に数値制約(何字以内 等)が紛れ込んでいないか — 紛れていればプロダクト都合の根拠があるか確認し、無ければ削る
4. 同一 skill 内で較正文が複数箇所に重複していないか
5. 転記変形(「事実だけで構成」)を使っている skill が、本当に転記専用か — 所見・推奨・次アクションを生成する節が 1 つでもあるなら標準較正文に戻す
6. 生データの全件掲載を要求している skill では、較正の対象が生データ以外の節に限定されているか
