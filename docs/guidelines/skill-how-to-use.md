# HOW_TO_USE.md 規約(人間向けリファレンス)

## 概要

各 skill (`skills/<name>/`) は、**人間が skill の使い方を確認するための実行経路外リファレンス** として `HOW_TO_USE.md` を 1 枚持つ。本ドキュメントはその配置場所・必須要件・「コーディングエージェントから参照させない」ための制約を定義する。新規 skill を追加するとき・既存 skill のオプションを変更したときの参照点とする。

## 背景

`SKILL.md` はホストエージェントが実行時に読むファイルであり、トークン効率と trigger 精度のために capability・起動条件・手順だけを書く([`skill-design.md`](skill-design.md))。一方で **人間が「このオプション何だっけ」「この組み合わせは何が起きる」を確認したい** ニーズは別にある。これを `SKILL.md` に書くと:

- エージェントが実行時に読み込みトークンを浪費する
- description に手順が混ざり、本来のフローが省略されるトラップ(skill-design 参照)を誘発する

そこで人間向けの説明を `HOW_TO_USE.md` に分離し、`SKILL.md` / `references/` からはリンクしないことでエージェントの実行経路から外す。

## 規約

### 配置と命名

- ファイル名は `skills/<name>/HOW_TO_USE.md` 固定(skill ルート直下)。
- 1 skill につき 1 枚。`references/` 配下には置かない(`references/` はエージェント向け参照ドキュメントの置き場であり、混同を招くため)。

### エージェントから参照させない制約(MUST)

- **`SKILL.md` および `references/` から `HOW_TO_USE.md` へリンクしない**。エージェントがファイルを開くのは「`SKILL.md` 本文」「`SKILL.md` / `references` からリンクされたファイル」に限られるため、リンクしなければ実行経路に乗らない。
- 冒頭に「人間向け・実行経路ではない・SSOT は該当スクリプト」を明記する NOTE ブロックを置く(下記テンプレート参照)。

> `gh skill install` は `skills/<name>/` を丸ごとコピーして配布するため `HOW_TO_USE.md` も配布先に同梱されるが、リンクしていない限りエージェントの実行フローには乗らない。

### SSOT との関係

- フラグ・サブコマンド・位置引数・default・排他/依存ルールの真実源 (SSOT) は **`scripts/` の引数解析スクリプト**(`parse-*.sh` 等)と `SKILL.md`。`HOW_TO_USE.md` はその派生ドキュメントである。
- **スクリプトに存在しないフラグを書かない**。排他・依存ルールはスクリプトが実際に enforce している(`exit 64` 等を返す)ものだけを記載する。
- スクリプトや `SKILL.md` を変更したら `HOW_TO_USE.md` も更新する。

### 必須・推奨セクション

skill が実際に持つ surface に合わせ、該当しないセクションは省く。

- 冒頭 NOTE ブロック(MUST)
- 概要(MUST): 何をする skill か + 起動形。サブコマンドを持つか単一コマンドかを明記。
- サブコマンド一覧(サブコマンドがあれば)
- 位置引数(あれば)
- フラグ一覧(フラグがあれば): 列挙値(severity / reviewer / diagram-type 等)も併記。
- 排他・依存ルール(スクリプトが enforce していれば)
- オプション組み合わせ別の特殊用法: 実例の `bash` ブロック + 注目すべき組み合わせの散文解説。

### discipline 系 skill の扱い

`scripts/` も `argument-hint` も持たない discipline / gate skill はオプション表を作らず、代わりに **概要・起動トリガー・フェーズ/進め方・使いどころ(他 skill との前後関係)** を人間向けに解説する。フラグを捏造しない。

## 冒頭 NOTE ブロックのテンプレート

```markdown
> [!NOTE]
> このファイルは **人間が <name> skill の使い方を把握するためのリファレンス** です。
> 実行経路ではありません(`SKILL.md` / `references/` からは一切リンクしておらず、
> コーディングエージェントが実行時に読むことを想定していません)。
>
> **フラグ・サブコマンド・default の真実源 (SSOT) は `scripts/<parse-script>.sh`** です。
> 本ファイルはその派生ドキュメントなので、スクリプトを変更したらここも更新してください。
```

discipline 系で SSOT スクリプトが無い場合は SSOT 行を
「**この skill はフラグを持たず、挙動の真実源は `SKILL.md`** です。」に置き換える。

## 規範例

書式の規範とする skill は、最初に `HOW_TO_USE.md` を持つ skill を追加した PR で本節に指定する。
